# ADR 0001 — C/C++ ABI (KR32 base, versioned)

**Status:** proposed  
**Date:** 2026-11-09  
**Decision:** D-010, D-011

## Context

KRCompiler needs a single versioned C/C++ ABI inherited from KR32 where
proven, with pointer-width/endianness parameters for retargetability
(plan.md D-010). The ABI is tied to the compiler version; the runtime is
rebuilt each release; no cross-version binary compatibility is promised
(plan.md D-011).

## Decision

- Base ABI: KR32 `../kr32/docs/abi.md` revision 1 (integer args in R0–R3,
  FP args in F0–F7, return in R0/R0-R1 and F0/F1, R7 frame pointer,
  R11 thread pointer, 16-byte stack alignment at public call boundaries,
  `sret` for aggregates > 8 bytes).
- Pointer-width and endianness are parameters of the target descriptor so
  KR16 (IP16, 16-bit pointers) and the future KR64 (LP64) can reuse the
  same ABI framework.
- `ABI_VERSION` is a monotonic integer embedded in objects and the runtime;
  the linker rejects mismatches.
- `extern "C"` symbols are unmangled; C++ symbols use Itanium-like mangling
  (`_Z` prefix).

## Consequences

- Positive: one ABI for all targets, common runtime and debug format,
  versioned for safe evolution.
- Negative: KR16's 16-bit `long` and no-FP profile require explicit
  documentation as a non-conforming embedded profile (plan.md §10.1).
- No cross-version binary compatibility: object files and runtime must be
  rebuilt for each compiler release.
